# VOICEVOX Core PHP FFI Feasibility Study

> **Scope**: Pure PHP (not Laravel-specific). This document describes a standalone PHP package that wraps the VOICEVOX Core C dynamic library via PHP's built-in FFI extension.

---

## Executive Summary

Implementing a PHP FFI wrapper for `VOICEVOX/voicevox_core` is **technically feasible** but carries important caveats. The C API is clean, callback-free, and opaque-pointer-based — all favorable properties for FFI. The primary challenges are:

1. **PHP FFI has no C preprocessor**: The official `voicevox_core.h` header uses `#ifdef` macros that must be stripped and resolved before passing to `FFI::cdef()`.
2. **ONNX Runtime must be loaded first**: The modern v0.16+ API requires loading `libonnxruntime` before `libvoicevox_core`, which requires an extra `FFI::cdef()` call.
3. **`ffi.enable` must be set**: On web server SAPIs this requires OPcache preloading; CLI is straightforward.
4. **NativePHP compatibility is limited**: The bundled PHP binary does not include FFI; a custom static-php-cli build is required.

The implementation is entirely possible for CLI tools, local scripts, and custom desktop apps (via NativePHP with a custom PHP binary). Production web server deployment is more complex but possible with proper OPcache preloading.

## 2. C API Architecture

The C API exposes **63 functions** across five logical groups[^2]:

### Opaque Handle Types

The API uses opaque C struct pointers — PHP cannot see their internals, only hold and pass them:

```c
typedef struct VoicevoxOnnxruntime   VoicevoxOnnxruntime;   // ONNX Runtime instance
typedef struct OpenJtalkRc           OpenJtalkRc;            // Japanese text analyzer
typedef struct VoicevoxSynthesizer   VoicevoxSynthesizer;    // Main synthesizer
typedef struct VoicevoxVoiceModelFile VoicevoxVoiceModelFile; // Voice model (.vvm file)
typedef struct VoicevoxUserDict      VoicevoxUserDict;        // User dictionary
```

### Initialization Sequence (Modern v0.16+ API)

```
voicevox_onnxruntime_load_once()    → VoicevoxOnnxruntime*
voicevox_open_jtalk_rc_new()        → OpenJtalkRc*
voicevox_synthesizer_new()          → VoicevoxSynthesizer*
voicevox_voice_model_file_open()    → VoicevoxVoiceModelFile*
voicevox_synthesizer_load_voice_model()
```

### TTS Pipeline

```
text → voicevox_synthesizer_create_audio_query() → AudioQuery JSON
                                                        ↓
                     voicevox_synthesizer_synthesis() → WAV bytes
```

Or shorthand: `voicevox_synthesizer_tts()` (text → WAV in one call)

### Memory Management

- All JSON strings and WAV buffers returned via `char**` / `uint8_t**` pointers are **C-heap allocated**
- Caller must free with `voicevox_json_free(char*)` and `voicevox_wav_free(uint8_t*)`
- Opaque handles freed with `voicevox_synthesizer_delete()`, `voicevox_open_jtalk_rc_delete()`, etc. (all null-safe since v0.16.1)

### Reference C Usage (from `example/cpp/unix/talk.cpp`)[^3]

```c
// 1. Load ONNX Runtime
VoicevoxLoadOnnxruntimeOptions ort_opts = voicevox_make_default_load_onnxruntime_options();
ort_opts.filename = "./voicevox_core/onnxruntime/lib/libvoicevox_onnxruntime.so.1.17.3";
const VoicevoxOnnxruntime *onnxruntime;
voicevox_onnxruntime_load_once(ort_opts, &onnxruntime);

// 2. Create OpenJTalk
OpenJtalkRc *open_jtalk;
voicevox_open_jtalk_rc_new("./voicevox_core/dict/open_jtalk_dic_utf_8-1.11", &open_jtalk);

// 3. Create Synthesizer
VoicevoxInitializeOptions opts = voicevox_make_default_initialize_options();
VoicevoxSynthesizer *synthesizer;
voicevox_synthesizer_new(onnxruntime, open_jtalk, opts, &synthesizer);

// 4. Load voice model (.vvm file)
VoicevoxVoiceModelFile *model;
voicevox_voice_model_file_open("models/vvms/0.vvm", &model);
voicevox_synthesizer_load_voice_model(synthesizer, model);

// 5. Synthesize
size_t wav_size;
uint8_t *wav;
voicevox_synthesizer_tts(synthesizer, "テスト", 0,
    voicevox_make_default_tts_options(), &wav_size, &wav);

// 6. Cleanup
voicevox_wav_free(wav);
voicevox_synthesizer_delete(synthesizer);
voicevox_voice_model_file_delete(model);
voicevox_open_jtalk_rc_delete(open_jtalk);
```

**Key patterns across all wrappers**:

| Concern | Pattern |
|---------|---------|
| Library loading | OS library name without path (if on `LD_LIBRARY_PATH`), or absolute path |
| String input | Convert PHP/Ruby/Go string → C char* |
| Output buffers | Double-pointer `**char` / `**uint8_t` + `*size_t` for WAV length |
| Result codes | Map integer codes to language errors/exceptions |
| Memory freeing | Always call `voicevox_wav_free()` and `voicevox_json_free()` |
| AudioQuery | Round-trip as JSON string — no need to parse C structs |

### Ruby Wrapper Pattern (Most Analogous to PHP FFI)[^5]

The Ruby `ffi` gem's `MemoryPointer` maps closely to PHP FFI patterns:

```ruby
# Ruby - double pointer pattern
size_ptr   = FFI::MemoryPointer.new(:int)
return_ptr = FFI::MemoryPointer.new(:pointer)

Voicevox::Core.voicevox_tts(text, speaker_id, opts, size_ptr, return_ptr)

data_ptr = return_ptr.read_pointer
data = data_ptr.read_string(size_ptr.read_int)
Voicevox::Core.voicevox_wav_free(data_ptr)
```

### Common Lisp CFFI Pattern (Closest to PHP FFI)[^6]

```lisp
(cffi:with-foreign-objects ((wav-length :uintptr)
                            (out-wav (:pointer :uint8)))
  (vv-tts text-c speaker-id options wav-length out-wav)
  ;; copy data, then free C pointer
  (cffi:voicevox_wav_free out-wav-ptr))
```

## 4. PHP FFI Capabilities

PHP FFI (`ext-ffi`) was introduced in **PHP 7.4** and is stable in PHP 8.x.

### Loading Methods[^7]

```php
// METHOD 1: FFI::cdef() — inline C declarations + library path (CLI-friendly)
$ffi = FFI::cdef(
    'int printf(const char *format, ...);',
    'libc.so.6'  // or 'libc.dylib' on macOS, 'msvcrt.dll' on Windows
);

// METHOD 2: FFI::load() — reads a .h file with #define FFI_LIB / #define FFI_SCOPE
$ffi = FFI::load('/path/to/mylib.h');

// METHOD 3: FFI::scope() — retrieve preloaded scope (OPcache preloading only)
$ffi = FFI::scope('MyLib');
```

### Core API Surface

| Method | Purpose |
|--------|---------|
| `FFI::cdef(string $code, ?string $lib)` | Parse C declarations, load library |
| `FFI::new(string $type, bool $owned=true)` | Allocate C memory |
| `FFI::free(CData $ptr)` | Free unmanaged memory |
| `FFI::cast(string $type, $ptr)` | Reinterpret-cast a pointer |
| `FFI::addr(CData $ptr)` | Get pointer-to (`&var` in C) |
| `FFI::string(CData $ptr, ?int $size)` | `char*` → PHP string |
| `FFI::sizeof(CData|CType $ptr)` | `sizeof()` equivalent |

### Cross-Platform Library Detection[^8]

```php
private static function getLibraryPath(): string
{
    return match (PHP_OS_FAMILY) {
        'Darwin'  => 'libvoicevox_core.dylib',
        'Windows' => 'voicevox_core.dll',
        default   => 'libvoicevox_core.so',
    };
}
```

### Singleton Loading Pattern (from `idealo/php-rdkafka-ffi`)[^9]

```php
private static ?FFI $ffi = null;

public static function getInstance(): FFI
{
    if (self::$ffi === null) {
        self::$ffi = FFI::cdef(
            file_get_contents(__DIR__ . '/voicevox_core_ffi.h'),
            self::getLibraryPath()
        );
    }
    return self::$ffi;
}
```

### Double-Pointer Output Buffer Pattern

PHP FFI maps to the same `**ptr` + `*size` pattern used across all language wrappers:

```php
// Allocate output slots
$wav_size = $ffi->new('uint64_t');   // uintptr_t (WAV byte count)
$wav_ptr  = $ffi->new('uint8_t*');   // pointer to WAV buffer

// Call C function
$result = $ffi->voicevox_synthesizer_tts(
    $synthesizer,
    "テスト",
    $style_id,
    $tts_options,
    FFI::addr($wav_size),  // uintptr_t*
    FFI::addr($wav_ptr)    // uint8_t**
);

// Read audio data into PHP string
$wav_data = FFI::string($wav_ptr, (int) $wav_size->cdata);

// Free C-allocated memory
$ffi->voicevox_wav_free($wav_ptr);
```

## 5. PHP FFI Incompatibilities with `voicevox_core.h`

The raw `voicevox_core.h` **cannot** be passed directly to `FFI::cdef()`. Six issues must be resolved by preprocessing:[^10]

### ❌ Issue 1: `#ifdef` / Conditional Compilation

The header has mandatory mutual-exclusive macro guards:
```c
#if !(defined(VOICEVOX_LINK_ONNXRUNTIME) || defined(VOICEVOX_LOAD_ONNXRUNTIME))
#error "either ... must be enabled"
#endif
```

Functions like `voicevox_onnxruntime_load_once()` are gated behind `#if defined(VOICEVOX_LOAD_ONNXRUNTIME)`. PHP FFI has no preprocessor — the blocks must be resolved manually.

**Fix**: Maintain a separate, pre-processed PHP FFI definition string for the `LOAD` branch (used by all non-iOS released binaries).

### ❌ Issue 2: `__declspec(dllimport)` (Windows)

Every exported function is wrapped in:
```c
#ifdef _WIN32
__declspec(dllimport)
#endif
void voicevox_json_free(char *json);
```

PHP FFI does not understand `__declspec`. Even on Linux/macOS, the parser will fail if this is present.

**Fix**: Strip all `#ifdef _WIN32 / __declspec(dllimport) / #endif` triplets from the FFI definition string.

### ❌ Issue 3: `uintptr_t` Not Known to PHP FFI

Used in 6 places including `voicevox_synthesizer_tts()`:
```c
uintptr_t *output_wav_length  // WAV byte count output
```

PHP FFI's parser does not include `<stdint.h>`, so `uintptr_t` is unknown.

**Fix**: Prepend `typedef uint64_t uintptr_t;` to the FFI definition string (valid on all 64-bit platforms).

### ❌ Issue 4: `#ifdef __cplusplus` Typed Enum Syntax

```c
enum VoicevoxAccelerationMode
#ifdef __cplusplus
  : int32_t   // C++ typed enum — PHP FFI sees this literally
#endif
{
```

**Fix**: Use `typedef int32_t VoicevoxAccelerationMode;` instead, and replicate enum values as PHP class constants.

### ❌ Issue 5: Fixed-Size Array Pointer Typedef

```c
typedef const uint8_t (*VoicevoxVoiceModelId)[16];  // pointer-to-array typedef
```

PHP FFI supports `uint8_t[16]` but the pointer-to-array typedef syntax is problematic.

**Fix**: Omit this typedef. Declare affected functions using `const uint8_t *model_id` instead (same ABI on 64-bit platforms).

### ⚠️ Issue 6: `bool` Type

The `bool` type from `<stdbool.h>` may need explicit declaration.

**Fix**: Prepend `typedef _Bool bool;` if PHP FFI's version doesn't have `bool` built-in.

### ⚠️ Issue 7: Static FFI Method Deprecations (PHP 8.5+)

PHP 8.5 deprecates calling certain `FFI` methods statically:
- `FFI::new()` → use `$ffi->new()` (instance method on an FFI object)
- `FFI::cast()` → use `$ffi->cast()`

`FFI::string()`, `FFI::memcpy()`, `FFI::addr()`, and `FFI::free()` remain usable as static methods.

```php
namespace YourOrg\Voicevox;

class VoicevoxFFI
```

### `VoicevoxSynthesizer.php` — Resource Wrapper

```php
<?php

namespace YourOrg\Voicevox;

use FFI;
use FFI\CData;

class VoicevoxSynthesizer
{
    private CData $handle;   // VoicevoxSynthesizer*
    private FFI $ffi;

    private function __construct(CData $handle, FFI $ffi)
    {
        $this->handle = $handle;
        $this->ffi = $ffi;
    }

    public static function create(
        VoicevoxOnnxruntime $onnxruntime,
        CData $openJtalk,
        bool $loadAllModels = false,
        int $cpuNumThreads = 0,
    ): self {
        $ffi = VoicevoxFFI::getInstance();

        $options = $ffi->voicevox_make_default_initialize_options();
        $options->acceleration_mode = 0;  // AUTO
        $options->cpu_num_threads = $cpuNumThreads;

        $synthPtr = $ffi->new('struct VoicevoxSynthesizer*');
        $result = $ffi->voicevox_synthesizer_new(
            $onnxruntime->handle(),
            $openJtalk,
            $options,
            FFI::addr($synthPtr)
        );

        ResultCode::check($result, $ffi);

        return new self($synthPtr, $ffi);
    }

    public function tts(string $text, int $styleId): string
    {
        $options = $this->ffi->voicevox_make_default_tts_options();

        $wavSize = $this->ffi->new('uint64_t');
        $wavPtr  = $this->ffi->new('uint8_t*');

        $result = $this->ffi->voicevox_synthesizer_tts(
            $this->handle,
            $text,
            $styleId,
            $options,
            FFI::addr($wavSize),
            FFI::addr($wavPtr)
        );

        ResultCode::check($result, $this->ffi);

        $wav = FFI::string($wavPtr, (int) $wavSize->cdata);
        $this->ffi->voicevox_wav_free($wavPtr);

        return $wav;
    }

    public function audioQuery(string $text, int $styleId): string
    {
        $jsonPtr = $this->ffi->new('char*');
        $result = $this->ffi->voicevox_synthesizer_create_audio_query(
            $this->handle,
            $text,
            $styleId,
            FFI::addr($jsonPtr)
        );

        ResultCode::check($result, $this->ffi);

        $json = FFI::string($jsonPtr);
        $this->ffi->voicevox_json_free($jsonPtr);

        return $json;
    }

    public function synthesis(string $audioQueryJson, int $styleId): string
    {
        $options = $this->ffi->voicevox_make_default_synthesis_options();

        $wavSize = $this->ffi->new('uint64_t');
        $wavPtr  = $this->ffi->new('uint8_t*');

        $result = $this->ffi->voicevox_synthesizer_synthesis(
            $this->handle,
            $audioQueryJson,
            $styleId,
            $options,
            FFI::addr($wavSize),
            FFI::addr($wavPtr)
        );

        ResultCode::check($result, $this->ffi);

        $wav = FFI::string($wavPtr, (int) $wavSize->cdata);
        $this->ffi->voicevox_wav_free($wavPtr);

        return $wav;
    }

    public function __destruct()
    {
        $this->ffi->voicevox_synthesizer_delete($this->handle);
    }
}
```

## 7. ONNX Runtime Loading

The modern v0.16+ API requires **explicit** ONNX Runtime loading before anything else. Three strategies are available:[^11]

### Strategy 1: `voicevox_onnxruntime_load_once()` (Recommended)

The cleanest approach — use the C API's own loading mechanism:

```php
$ffi = VoicevoxFFI::getInstance();

// Ask voicevox_core itself for the versioned filename
$versionedName = FFI::string($ffi->voicevox_get_onnxruntime_lib_versioned_filename());
// e.g. "libvoicevox_onnxruntime.so.1.17.3"

$opts = $ffi->voicevox_make_default_load_onnxruntime_options();
$opts->filename = './voicevox_core/onnxruntime/lib/' . $versionedName;

$ortPtr = $ffi->new('struct VoicevoxOnnxruntime*');
$result = $ffi->voicevox_onnxruntime_load_once(
    $opts,
    FFI::addr($ortPtr)
);
```

### Strategy 2: Pre-load via Blank `FFI::cdef('')` (Scala `System.load()` Equivalent)

```php
// Pre-load ONNX Runtime into process memory with no function declarations
// This calls dlopen() internally, satisfying voicevox_core's linker dependency
FFI::cdef('', '/path/to/voicevox_core/onnxruntime/lib/libvoicevox_onnxruntime.so.1.17.3');

// Now load voicevox_core — onnxruntime symbols are already resolved
$ffi = FFI::cdef(/* declarations */, '/path/to/libvoicevox_core.so');
```

### Strategy 3: `LD_LIBRARY_PATH` Environment Variable (Simplest)

```sh
export LD_LIBRARY_PATH=/path/to/voicevox_core/onnxruntime/lib:$LD_LIBRARY_PATH
php your_script.php
```

## 8. Platform Support & Distribution

### PHP.ini Requirements

| Setting | CLI | Web Server |
|---------|-----|-----------|
| `ffi.enable=true` | Default ✅ | Must set explicitly |
| `ffi.enable=preload` | Not needed | Production mode; requires preload script |
| `opcache.enable=1` | Not needed | Required for `preload` mode |
| `zend.max_allowed_stack_size=-1` | If using callbacks | Required in PHP 8.3+ |

**For CLI use**: No configuration needed beyond PHP having FFI compiled in. Check with `php -r "var_dump(extension_loaded('ffi'));"`.

### Library Search Path

| OS      | Search Location                       | Override                                          |
|---------|---------------------------------------|---------------------------------------------------|
| Linux   | `/usr/lib`, `/usr/local/lib`          | `LD_LIBRARY_PATH`                                 |
| macOS   | `/usr/local/lib`, `/opt/homebrew/lib` | `DYLD_LIBRARY_PATH`, `DYLD_FALLBACK_LIBRARY_PATH` |
| Windows | `PATH` directories                    | Absolute path in `FFI::cdef()`                    |

**Recommendation**: Always use absolute paths in `FFI::cdef()` to avoid search-path issues:
```php
$libPath = '/path/to/voicevox_core/libvoicevox_core.so';
$ffi = FFI::cdef($declarations, $libPath);
```

### Package Distribution Pattern

No Packagist packages bundle native `.so`/`.dll` files. The community consensus:[^12]

1. **Require `ext-ffi` in `composer.json`** — fails composer install if FFI not available
2. **Bundle the `.h` file** (pre-processed, without macros) in `src/headers/`
3. **Document native library installation** in README
4. **Support user-configurable paths** via environment variables or constructor arguments

```php
// Allow user to specify the library path
$voicevox = new Voicevox(
    libraryPath: env('VOICEVOX_CORE_LIB_PATH', 'libvoicevox_core.so'),
    onnxruntimePath: env('VOICEVOX_ONNXRUNTIME_PATH', ''),
    openJtalkDictDir: env('VOICEVOX_DICT_DIR', ''),
```

## 9. NativePHP Compatibility

### Default Binary: FFI Not Included[^13]

The NativePHP bundled PHP binary (`NativePHP/php-bin`) does **not** include the `ext-ffi` extension. The bundled extensions list omits `ffi`.

### Workaround: Custom PHP Binary

NativePHP supports a custom binary path:

```php
// config/nativephp.php
'binary_path' => env('NATIVEPHP_PHP_BINARY_PATH', null),
```

**Steps to enable FFI in NativePHP**:
1. Build a custom PHP binary with `static-php-cli` that includes `ffi`
2. Set `NATIVEPHP_PHP_BINARY_PATH` to point to the custom binary
3. Bundle VOICEVOX Core libraries with the app

**Linux caveat**: Static PHP builds with musl libc (Alpine-based) **cannot load dynamic libraries** via FFI due to static linking constraints. A glibc-based build is required for Linux. macOS and Windows work without this limitation.

### Practical Recommendation for NativePHP

Given the complexity, VOICEVOX Core FFI in NativePHP is best suited for:
- macOS desktop apps (arm64/x64) — most straightforward
- Windows desktop apps — DLL loading works reliably
- Linux apps built with glibc target — requires careful `static-php-cli` configuration
